How the trace works
-------------------
run-presend-trace.mjs copies the current client lib to a disposable .dart_tool
folder and asserts unique source anchors before adding synchronous marks at
send, submit and refresh entry. A zone carries actual refresh caller/instance
through Future.any's cancellation wrapper. Only the temporary compiler package
map points at this copy; lib, manifests and locks remain unchanged. Instrumented
refresh still calls and awaits the original implementation; no read is skipped.
The extra diagnostic wrapper means timings are fixture order/overlap evidence,
not consumer latency measurements. The singleflight Future identity is tested.

presend_fixture.dart records per-session instance, operation/turn identity,
caller stack, preparing/submitting state, refresh already in flight, request
start/end, overlapping HTTP IDs, request bodies and canonical/projection response
revision, generation, throughRevision, active turn and mutation receipts. Bodies
are safe ONLY because this fixture owns synthetic data. Its HTTP recorder rejects
non-loopback destinations. Never deploy this recorder into a consumer. HTTP
stream headers are distinguished from whole-stream completion.

Session polling is disabled in the fixture to isolate explicit preparation and
admission; packaged UI catalog activity is still separately recorded. This does
not reproduce Preview scheduling or its aggregate request window. Draft/file
races are covered by the existing focused controller/store/composer tests, not
by a new device-level file-upload replay.

The Node gateway uses the exact local JS build with actual Postgres persistence
adapters and a fresh in-memory PGlite PostgreSQL engine. It has an explicitly
synthetic provider, no tools, no credentials, no external provider URLs. A
fixture-only opt-in /test/trace-auth switch simulates the HOST authorization
boundary returning 403 on protected requests. It does not qualify any consumer
identity service, token refresh, RLS, external PostgreSQL server or multi-process
locking. Concurrent cases are deterministically interleaved real HTTP requests.

Safety conclusions and review candidate
--------------------------------------
* Keep the first preparation refresh: a remote canonical change since selection
  must influence the newly frozen expectedRevision, and busy/preparing/error
  states must prevent preparation. A cached document is not a freshness proof.
* Singleflight already joins overlap within one session; it cannot remove the
  observed sequential pair after the earlier Future has completed. No lifetime
  coalescing, TTL extension, slower cadence, raised limits, or 429 bypass.
* Keep direct prepare/submit and restored exact-retry refresh semantics. The
  prepare/retain gap can be arbitrarily long. Preserve operation, message, turn,
  mutation and start identities; never regenerate or rebase on an uncertain ack.
* Server current authorization, canonical CAS and duplicate receipts remain the
  authority even after a successful read. The last read cannot close a race
  immediately before append; remote changes after it must still fail safely.
* New draft edits (including returning to identical text), newly selected files,
  scope changes and disposal must survive an older admission callback. Only the
  captured text version/file IDs can be reconciled. Device origin never goes on
  the wire; cleanup failure retains recoverability.
* Generation reset, preparing/error status, page cursors, pending navigation and
  related context/approval pages are separate from a complete delta watermark.
  Window revision alone is insufficient: _changesAfter advances only after the
  changes cursor is exhausted (display_window.dart:400).

Smallest review candidate: for the immediate fresh-send path only, keep the
second authorized control and investigate omitting JUST its repeated display
changes request when a one-use preparation witness proves the same session,
account, conversation, generation, canonical AND projection heads, with a fully
consumed changes watermark and no pending navigation/reset/error. Expire the
witness for direct submit, restored retry, invalidation or differing heads;
retain all related/context reads that are required. This would save ONE request
in the demonstrated unchanged case. No such optimization is implemented or
qualified here. Removing the entire second refresh is not supported as a
behavior-preserving change by the concurrent-turn/auth counterexamples. A later
candidate needs its own equivalence tests/review, including navigation and
partial changes pagination, before any publication.
