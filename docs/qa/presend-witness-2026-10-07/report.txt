Private proof and bounds
------------------------
Only immediate session.sendMessage creates a local _PreparedChanges after its
preparation completes. It is passed down the private submit call chain and is
never serialized, attached to a public submission, globally cached or retained
on the session. A failed retain drops it. Direct prepare/submit and all journal
retry/reconstruction paths pass no witness. Joined preparation refreshes cannot
create it. Every subsequent session refresh attempt/stream wake invalidates it.

Capture requires a ready active account/session display, the exact nullable
prepared document revision, and a fully consumed CHANGES operation. Initial
pages are not proof. The window records _consumedChanges only after merging the
response; a cursor, deferred response record or trim prevents that flag. The
predicate also checks _changesAfter against the projection head, window head and
generation, no read/selection/latest/content work outstanding, no error or failed
operation, no newer window, following latest, and no deferred retained records.
Session related/approval work, remaining related pagination, truncation and
pending automatic display work fail closed. Available older transcript/history
pages are not walked or treated as pending delta consumption.

After the SECOND authorized control succeeds, consume spends the witness before
checking it. It requires identical session, window, activation, window selection
and previous control; unchanged workspace selection/window version, local
preparation/display-read/observation generations and related/approval epochs;
unchanged nullable document revision; plus matching fresh conversation,
canonical head, projection head and generation, ready and no active remote turn.
No null documentRevision is coerced to zero. Canonical and display zero are
compared as their own control fields; admission expectedRevision remains null.

Account identity is bound by the EXISTING account-owned client/controller/session
lifetime contract: dispose on logout/account change. A replacement account or
client cannot inherit the private witness. Workspace selection roundtrips,
window selection/navigation/refresh/retry/content reads, stream observation,
reset and generation changes invalidate it. Keeping the same controller while
silently changing its host principal violates the existing supported lifecycle;
the SDK has no principal identifier in control and does not hash/store bearer
headers to manufacture one. Current host authorization still runs on every kept
control, append and start. Replacement with disposal and revocation at control
and append are tested. No new host identity API or protocol is introduced.

On failure/uncertainty the old full refresh path remains. Omitting changes is
the only conditional skip. Related/context/history logic still runs below that
branch. All original append receipts, active/exact-turn checks, requested-turn
verification, immutable CAS and start authorization remain unchanged. Changes
after control still conflict at admission. Retry never regenerates an operation.
